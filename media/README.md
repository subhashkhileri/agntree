# Media: what to record and how

The website and the README show Agntree with the files in this folder. Drop a file in with the right name and the site picks it up on the next build; nothing else needs editing. Until a clip exists, the landing page plays an illustrated VS Code window in the hero, and the README shows two generated GIFs. Real recordings are more convincing than illustrations, so they are worth making.

| File | Used by |
| --- | --- |
| `og.png` | Link previews. Generated by `npm run build:social-card`; do not record it |
| `demo-<scene>.gif` | The README, the Marketplace page, and the landing page on a phone: one short loop per scene of the illustrated window. Generated by `npm run build:demo-gifs`; do not record them |
| `hero.*` | Top of the landing page, in place of the illustrated window, and the README once you swap it in |
| `sessions.*`, `worktrees.*`, `fork.*`, `find-session.*`, `notifications.*`, `changes.*`, `agent-panel.*` | Not shown by the site yet. Use them in the README's feature sections, in release notes, and in posts |

## Formats

For each clip, export three files with the same name:

| File | Purpose | Target |
| --- | --- | --- |
| `<name>.webm` | The video the site plays (VP9, no audio) | Under 1.5 MB |
| `<name>.mp4` | Fallback for Safari (H.264, no audio) | Under 2.5 MB |
| `<name>.png` or `.webp` | The frame shown before the video loads | Under 200 KB |

A still image by itself also works: `changes.png` alone shows as a screenshot. For the README and the Marketplace page, which cannot play video, also export `hero.gif` (under 5 MB, 15 fps, 960 px wide).

Record at **1600×1000** (16:10) and export at that size. The site scales it down, and it stays sharp on high-density screens.

## Set up the window once

A demo is judged in the first two seconds, so the frame has to be clean.

1. **Use a throwaway profile:** `code --profile agntree-demo`. Install only Agntree, Claude Code, and Codex in it.
2. **Theme:** Dark Modern, the VS Code default. Viewers recognise it at once.
3. **Zoom:** run **View: Zoom In** twice (`window.zoomLevel` 2). Text must be readable in a 700 px wide embed.
4. **Hide the noise:** close the secondary side bar, the minimap, the status bar's extra items, and every notification. Turn off the breadcrumbs. Keep the Activity Bar, so the Agntree icon is visible.
5. **Size the layout:** Agntree sidebar about 380 px wide, the terminal in the editor area or a tall bottom panel. The sidebar should fill roughly a third of the frame.
6. **Use a demo repository,** not your real work. A small, believable project called `storefront` matches the drawing on the site: worktrees `main`, `feature/search`, and `checkout-tax-rounding`, with three or four sessions that have real, specific names ("Fix flaky cart total test", "Add search filters", "Round tax per line item").
7. **No secrets on screen:** no real paths with your name (use `~/code/storefront`), no API keys, no private repository names, no email in the terminal prompt. Set a short prompt: `PS1='$ '`.
8. **Slow down.** Move the pointer deliberately and pause half a second before each click. Do not type live; paste the prompt, or cut the typing in the edit.

## The clips

Each clip shows **one idea**, loops cleanly, and needs no sound or caption to follow. Start and end on the same resting frame so the loop does not jump.

### `hero` (10 to 14 seconds): the whole pitch

This is the one that matters most. It has to show several agents under control at once.

1. Open on the sidebar: `storefront` expanded, three worktrees, five or six sessions, **two marks animating as "working"** with Claude Code and Codex icons mixed.
2. Click a finished session. Its terminal opens with the conversation resumed.
3. A notification appears: "Add search filters finished (storefront · feature/search)". Click **Open**. The view jumps to that session.
4. Rest on the sidebar for one second.

Tip: start two real agents on a slow task a minute before recording, so the working marks are real.

### `sessions` (6 to 8 seconds): click to resume

1. Sidebar with several sessions, no terminal open.
2. Click one. The terminal opens and the agent shows the earlier conversation.
3. Click a second session from a different agent. Its terminal opens beside the first.

### `worktrees` (10 to 12 seconds): repository to running agent

1. Hover the repository row and select **Create Worktree…**.
2. Choose **New branch**, type `fix/login-redirect`, confirm.
3. The worktree row appears. Select **+** on it and choose **Claude Code**.
4. The terminal opens in the new directory. Hold on the path in the terminal for a moment.

### `fork` (8 to 10 seconds): two approaches from one conversation

1. Right-click a session and choose **Fork Session to New Worktree…**.
2. Accept the branch name.
3. A new worktree appears with the forked session under it, and its terminal opens with the same history.
4. Rest with both sessions visible in the tree.

### `find-session` (8 to 10 seconds): describe it, get it

1. Press `Ctrl+Alt+F`. Paste "the one where we fixed the flaky cart test".
2. Cut the wait in the edit, so the search appears to take about two seconds. Do not show a long spinner.
3. The match appears in the Find Session view. Click it, and the session resumes.

### `notifications` (6 to 8 seconds): the agent calls you

1. You are in an editor file. An agent is working in another worktree (its mark is animating in the sidebar).
2. The notification appears: "<name> needs your input". Click **Open**.
3. The terminal shows Claude Code's permission prompt.

Use a Claude Code session for this one: "needs your input" is the strongest moment, and only Claude Code reports it.

### `changes` (a still, or 6 seconds): review the edits

Select a worktree where an agent edited four to six files. Show the **Changes** panel with staged and unstaged files and their line counts, and one diff open in the editor. A still image is enough here.

### `agent-panel` (8 seconds): terminal to panel

1. A Claude Code session is open in its terminal.
2. Right-click its row and choose **Open in Claude Code UI**. The terminal closes and the same conversation opens in the Claude Code panel.

## Recording tools

| System | Record with | Notes |
| --- | --- | --- |
| macOS | [Screen Studio](https://screen.studio) (paid) or the built-in `Cmd+Shift+5` | Screen Studio adds smooth pointer movement and zoom, which is what makes product demos look polished |
| Windows | [ScreenToGif](https://www.screentogif.com) or OBS | |
| Linux | OBS, or [Kooha](https://github.com/SeadVE/Kooha) on GNOME | Record a fixed 1600×1000 region |

## Export commands

With [ffmpeg](https://ffmpeg.org) installed, from a recording called `raw.mov`:

```bash
# WebM for the site
ffmpeg -i raw.mov -an -vf "fps=30,scale=1600:-2" -c:v libvpx-vp9 -b:v 0 -crf 36 hero.webm

# MP4 fallback
ffmpeg -i raw.mov -an -vf "fps=30,scale=1600:-2" -c:v libx264 -crf 26 -pix_fmt yuv420p -movflags +faststart hero.mp4

# Poster: the first frame
ffmpeg -i raw.mov -frames:v 1 -vf "scale=1600:-2" hero.png

# GIF for the README and Marketplace
ffmpeg -i raw.mov -vf "fps=15,scale=960:-2:flags=lanczos,split[a][b];[a]palettegen=max_colors=128[p];[b][p]paletteuse=dither=bayer" hero.gif
```

Raise `-crf` if a file is over its target size.

## After recording

1. Put the files in this folder and run `npm run build:site`. Open `_site/index.html` to check them.
2. In `README.md`, replace `media/demo-sessions.gif` in the image near the top with `media/hero.gif`.
3. Upload `og.png` as the repository's social preview: GitHub → Settings → General → Social preview.
4. Commit the files. The site redeploys on merge to `main`; the Marketplace page updates on the next release.

The Marketplace shows the README, so the hero GIF covers it. Two stills also help in the README's feature sections if you want them: the sidebar with mixed agents (`sessions.png`) and the Changes panel (`changes.png`). Keep each under 300 KB.
